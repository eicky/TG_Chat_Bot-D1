# keyword-filter 增量规格

## Purpose

补全正则 ReDoS 防护：现有危险形态检查只覆盖括号分组构造，无括号的连续量词链可绕过。

## MODIFIED Requirements

### Requirement: 匹配规则与正则防护

屏蔽词默认按不区分大小写的子串匹配；以 `re:` 前缀声明的条目按正则匹配。正则匹配 MUST 有 ReDoS 防护：模式长度受限、拒绝已知危险形态、被检文本截断至安全长度；非法或被拒绝的正则 MUST 视为不匹配且不报错。

危险形态检查 MUST 同时覆盖不含括号分组的构造：以量词总数上限拒绝形如 `a*a*a*…` 的连续量词链。该上限 MUST 高于常规屏蔽词正则的实际用量，以免误伤管理员的正常配置。

#### Scenario: 子串匹配不区分大小写

- **WHEN** 屏蔽词为"SPAM"，用户发送"spam 消息"
- **THEN** 判定命中

#### Scenario: 正则条目匹配

- **WHEN** 屏蔽词为 `re:加微信\d+`，用户发送"加微信12345"
- **THEN** 判定命中

#### Scenario: 危险正则被拒绝

- **WHEN** 屏蔽词为 `re:(a+)+$` 这类高风险回溯模式
- **THEN** 该条目视为不匹配，其余条目正常生效，系统不超时不崩溃

#### Scenario: 无括号量词链被拒绝

- **WHEN** 屏蔽词为 `re:a*a*a*a*a*a*a*a*a*a*a*a*a*a*a*a*a*a*a*a*b` 这类无分组的连续量词链，用户发送可触发回溯的文本
- **THEN** 该条目视为不匹配，匹配过程不出现可观测的耗时增长，其余条目正常生效

#### Scenario: 正常正则不被误伤

- **WHEN** 管理员配置 `re:[Vv][Xx]\s*[:：]?\s*\w+`、`re:客服\s*QQ\s*\d{5,}` 等含多个量词的常规屏蔽词
- **THEN** 这些条目正常参与匹配，不被危险形态检查拒绝
