# topic-relay 增量规格

## Purpose

修复话题失效重建时「触发重建的那条消息」被静默吞掉的缺陷。

## MODIFIED Requirements

### Requirement: 话题失效恢复

用户专属话题不可用时系统 MUST 自动恢复，不得陷入持续静默失败：话题已被删除（thread not found 类错误）时清除失效映射并在该用户下次消息时重新创建话题；话题被关闭（TOPIC_CLOSED 错误）时 MUST 先尝试自动重新打开话题并重试发送，重开失败再按删除处理。其他临时性错误（限流、网络）MUST 不触发映射清除。

触发话题重建的那条用户消息本身 MUST NOT 丢失：当转发因话题失效而失败、系统清除映射后，该次处理 MUST 请求 Telegram 稍后重投（而非以成功状态结束），使该消息在重投时经由新建话题送达管理群。任何用户消息 MUST NOT 出现「未送达管理群、未提示用户、且不会被重投」的三重静默结局。

#### Scenario: 话题被管理员删除

- **WHEN** 用户话题已被删除，该用户又发来消息
- **THEN** 系统清除旧映射，为该用户创建新话题并完成转发（允许提示用户重发一次）

#### Scenario: 触发重建的消息不得丢失

- **WHEN** 用户话题已被删除，该用户发来一条消息导致转发失败并清除映射
- **THEN** 本次处理请求 Telegram 重投，重投时该消息经新建话题成功送达管理群，用户最终获得已送达标记

#### Scenario: 话题被管理员关闭

- **WHEN** 用户话题被关闭，该用户又发来消息
- **THEN** 系统自动重新打开该话题并完成转发，对话历史保留

#### Scenario: 临时错误不清映射

- **WHEN** 转发因 Telegram 限流暂时失败
- **THEN** 话题映射保持不变，不触发重建
