# topic-relay 增量规格

## Purpose

用户私聊消息与管理群论坛话题之间的双向消息中继：每个用户对应一个专属话题，话题即该用户的身份标识与对话容器；管理员在话题内像普通聊天一样与用户对话。

## ADDED Requirements

### Requirement: Webhook 请求鉴别
系统 MUST 校验 Telegram webhook 请求头 `X-Telegram-Bot-Api-Secret-Token` 与配置的密钥一致（常量时间比较），不一致或缺失时拒绝请求。

#### Scenario: 伪造请求被拒绝
- **WHEN** 收到不带正确 secret token 的 POST webhook 请求
- **THEN** 系统返回 403，不处理任何内容

### Requirement: Update 幂等处理
对同一用户的同一 `update_id`，系统 MUST 至多处理一次；Telegram 因超时重投同一 update 时不得重复转发消息。

#### Scenario: 重投的 update 不重复转发
- **WHEN** Telegram 将已处理过的 update 再次投递
- **THEN** 系统直接确认成功，不再次转发该消息

### Requirement: 用户消息限流
非管理员用户的私聊消息 MUST 受频率限制；超限消息不被转发，且提示语在短时间窗口内 MUST 只发送一次（防抖）。

#### Scenario: 高频消息被限流
- **WHEN** 用户在 2 秒内发送超过限额条数的消息
- **THEN** 超限消息不被转发，用户收到一次"请求过于频繁"提示

### Requirement: 专属话题创建
已验证用户的首条中继消息 MUST 触发在管理群创建该用户的专属论坛话题，话题名包含用户名称与数字 ID；同一用户并发到达的多条消息 MUST 只产生一个话题，且不得通过锁轮询等待实现。

#### Scenario: 首条消息创建话题
- **WHEN** 已验证且无话题映射的用户发送第一条消息
- **THEN** 管理群出现一个以"名称 | ID"命名的新话题，且该消息被转发到此话题

#### Scenario: 并发消息不重复建话题
- **WHEN** 同一用户的多条消息在同一时刻到达
- **THEN** 管理群只创建一个话题，所有消息都转发到该话题

### Requirement: 消息类型过滤
系统 MUST 支持按消息类型控制是否接收转发，共 7 类独立开关：转发消息、频道来源转发、媒体文件（图片/视频/文档）、语音/音频、贴纸/GIF、链接、纯文本。一条消息按首个命中的类型判定（优先级：转发 > 语音/音频 > 贴纸/GIF > 媒体 > 链接 > 纯文本；转发自频道的消息按频道开关判定）。命中已关闭类型的消息 MUST 不被转发并提示用户"系统不接收该类型"；管理员 MUST 豁免过滤。

#### Scenario: 关闭类型被拦截
- **WHEN** 贴纸/GIF 开关关闭，用户发送一张贴纸
- **THEN** 消息不被转发，用户收到"系统不接收 贴纸/GIF"提示

#### Scenario: 开启类型正常转发
- **WHEN** 贴纸/GIF 开关开启，用户发送一张贴纸
- **THEN** 贴纸正常转发到其专属话题

#### Scenario: 频道转发单独判定
- **WHEN** 频道转发开关关闭而普通转发开关开启，用户转发一条频道消息
- **THEN** 消息被拦截并提示

### Requirement: 消息转发与送达标记
已验证且未屏蔽用户的消息 MUST 被转发到其专属话题；转发成功后系统 MUST 给用户的原消息添加已送达表情回应。

#### Scenario: 文本消息转发并标记
- **WHEN** 已验证用户发送一条文本消息
- **THEN** 消息出现在其专属话题中，且用户侧原消息获得 👍 表情回应

### Requirement: 管理员回复转达
管理员在用户专属话题内发送的消息 MUST 被复制发送给对应用户；发送失败（如用户已停用机器人）时 MUST 在话题内提示失败。

#### Scenario: 话题内回复送达用户
- **WHEN** 管理员在某用户的话题内发送消息
- **THEN** 该用户在私聊中收到这条消息

#### Scenario: 用户已停用机器人
- **WHEN** 管理员回复的目标用户已 block 机器人
- **THEN** 话题内出现发送失败提示，系统不崩溃

### Requirement: 话题失效恢复
用户专属话题不可用时系统 MUST 自动恢复，不得陷入持续静默失败：话题已被删除（thread not found 类错误）时清除失效映射并在该用户下次消息时重新创建话题；话题被关闭（TOPIC_CLOSED 错误）时 MUST 先尝试自动重新打开话题并重试发送，重开失败再按删除处理。其他临时性错误（限流、网络）MUST 不触发映射清除。

#### Scenario: 话题被管理员删除
- **WHEN** 用户话题已被删除，该用户又发来消息
- **THEN** 系统清除旧映射，为该用户创建新话题并完成转发（允许提示用户重发一次）

#### Scenario: 话题被管理员关闭
- **WHEN** 用户话题被关闭，该用户又发来消息
- **THEN** 系统自动重新打开该话题并完成转发，对话历史保留

#### Scenario: 临时错误不清映射
- **WHEN** 转发因 Telegram 限流暂时失败
- **THEN** 话题映射保持不变，不触发重建

### Requirement: 置顶资料卡
新话题创建时系统 MUST 向话题发送用户资料卡（名称、ID、时间、备注）并置顶；资料卡 MUST 携带屏蔽/解封与备注操作按钮。

#### Scenario: 新话题带置顶资料卡
- **WHEN** 用户专属话题被创建
- **THEN** 话题顶部有置顶的资料卡，含用户名称、ID 与操作按钮

### Requirement: 编辑消息通知
用户编辑已发送的私聊消息时，系统 MUST 在其专属话题内发送包含新内容的编辑提示。

#### Scenario: 用户编辑消息
- **WHEN** 已有话题的用户编辑了此前发送的消息
- **THEN** 话题内出现"用户修改了消息"提示及新文本

### Requirement: 营业状态自动回复
营业状态为休息中时，用户来消息 MUST 收到预设忙碌提示；同一用户在冷却期内 MUST 不重复收到提示；消息本身仍正常转发。

#### Scenario: 休息模式自动回复一次
- **WHEN** 休息模式开启，用户在冷却期内发送多条消息
- **THEN** 用户只收到一次忙碌提示，消息全部正常转发到话题
