# moderation 增量规格

## Purpose

管理员对用户的人工管控：手动屏蔽与解封（资料卡与黑名单话题双入口、状态双向同步）、强制重置用户验证状态。

## ADDED Requirements

### Requirement: 手动屏蔽与解封
管理员点击资料卡上的屏蔽/解封按钮 MUST 切换该用户的屏蔽状态并重置违规计数；被屏蔽用户的消息 MUST 不再转发，用户收到屏蔽提示（短时间窗口内防抖只提示一次）；/start MUST 不解除屏蔽。

#### Scenario: 屏蔽用户
- **WHEN** 管理员点击某用户资料卡的"🚫 屏蔽"按钮
- **THEN** 该用户被屏蔽，资料卡按钮变为"✅ 解封"，其后续消息不转发

#### Scenario: 屏蔽用户尝试自救
- **WHEN** 被屏蔽用户发送 /start 或普通消息
- **THEN** 屏蔽保持不变，用户在防抖窗口内至多收到一次屏蔽提示

### Requirement: 黑名单话题同步
用户被屏蔽（手动或自动）时，共享"黑名单"话题 MUST 生成含解封按钮的用户卡片；解封时该卡片 MUST 被删除；从资料卡或黑名单卡片任一入口操作，两处状态 MUST 保持一致。黑名单共享话题在并发场景 MUST 只创建一次；被删除时 MUST 清空存储的话题标识并在下次需要时自动重建，被关闭时 MUST 先尝试自动重新打开、失败再按删除处理，临时性 API 错误 MUST 不触发重建；共享话题创建完成前允许本次卡片生成延后，屏蔽状态本身 MUST 即时生效。

#### Scenario: 屏蔽生成黑名单卡片
- **WHEN** 用户被屏蔽
- **THEN** 黑名单话题出现该用户卡片，含"✅ 解除屏蔽"按钮

#### Scenario: 黑名单话题解封
- **WHEN** 管理员点击黑名单卡片的解封按钮
- **THEN** 用户恢复正常，黑名单卡片删除，资料卡按钮同步变回"🚫 屏蔽"

#### Scenario: 黑名单话题被误删后自愈
- **WHEN** 管理员误删了黑名单话题，随后有用户被屏蔽
- **THEN** 系统自动重建一个新的黑名单话题并生成卡片

### Requirement: 强制重置验证
管理员私聊发送 `/reset <用户ID>` MUST 将目标用户重置为未验证状态并作废其验证 nonce（不改变屏蔽状态与话题映射），同时通知目标用户重新验证；参数缺失或非数字时 MUST 返回用法说明。

#### Scenario: 重置用户验证
- **WHEN** 管理员发送 `/reset 123456789`
- **THEN** 目标用户回到未验证状态，收到重新验证提示，管理员收到确认

#### Scenario: 参数错误
- **WHEN** 管理员发送 `/reset abc`
- **THEN** 返回用法说明，不做任何变更

### Requirement: 操作权限校验
屏蔽、解封、备注、重置等管理操作 MUST 校验操作者属于 `ADMIN_IDS`；非管理员触发（含点击按钮）MUST 被拒绝且无副作用。

#### Scenario: 非管理员点击管理按钮
- **WHEN** 非管理员用户点击资料卡或黑名单卡片上的按钮
- **THEN** 收到无权限提示，用户状态无任何变化

### Requirement: 用户备注管理
管理员在用户话题内发送 `/note <内容>` MUST 保存该用户备注并同步刷新资料卡显示；`/note` 不带内容 MUST 清除备注。

#### Scenario: 设置备注
- **WHEN** 管理员在某用户话题内发送 `/note 重要客户`
- **THEN** 备注保存成功，置顶资料卡即时显示"备注: 重要客户"

#### Scenario: 清除备注
- **WHEN** 管理员在话题内发送不带内容的 `/note`
- **THEN** 该用户备注被清除，资料卡不再显示备注行
