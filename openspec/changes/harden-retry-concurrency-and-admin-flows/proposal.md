## Why

当前 Worker 虽已修复验证码直接绕过、话题删除后当条消息丢失和验证页 XSS，但并发 update、HTTP 500 重投、用户限流和话题恢复之间仍存在竞态，可导致同一 update 重复处理、未送达消息被限流路径以 200 确认、迟到请求覆盖新话题映射。审查还确认了编辑消息绕过验证、初始资料卡缺少管理按钮、正则防护仍可绕过、验证与配置切换不即时生效等缺陷；现有 140 项冒烟测试未真实模拟同一 update 重投及这些交错时序。

本变更统一修复上述问题，先建立可验证的消息处理与状态所有权语义，再修复依赖这些语义的验证、管理和配置路径，避免继续以互相冲突的局部补丁处理可靠性问题。

## What Changes

- 为 webhook update 引入原子 claim、租约与完成状态：同一 `update_id` 同时只能有一个处理者，处理者失败或超时后允许安全接管，成功完成前不得永久标记为已处理。
- 将用户限流判定与 update 首次处理绑定；同一 update 的 Telegram 重投不重复消耗限流额度，任何返回 500 的原 update 均可使用相同 `update_id`、`message_id` 重投并最终送达或得到明确的永久失败结果。
- 为用户话题和黑名单话题创建引入 fencing token / 条件更新；过期持有者不得覆盖新映射，针对旧话题的迟到错误不得清除已经建立的新映射。
- 统一 Telegram 错误分类：区分话题删除、话题关闭、永久 4xx、429、5xx 与网络异常；`reopenForumTopic` 的临时失败不得清空映射，管理员回复的临时失败必须请求重投，永久失败必须给出可见提示并终止重投。
- 使 `edited_message` 遵守当前用户验证、屏蔽、关键词和消息类型策略，防止 `/reset` 后通过编辑旧消息绕过验证。
- 新话题的初始置顶资料卡携带屏蔽/解封和备注操作按钮，保证人工管理入口首次即可用。
- 以可解析、不可被转义字符绕过的安全匹配方案替代现有正则字符串黑名单，覆盖 `?` 量词链、转义括号和其他灾难性回溯构造，同时保留受支持的管理员匹配能力。
- 问答开关关闭后，已有 `qa_pending` 用户立即按剩余验证流程推进；验证码 nonce 的下发与消费改为原子操作，避免并发按钮互相失效或同一 nonce 被重复消费。
- 未验证用户无论发送 `/start` 还是普通首消息都收到欢迎语与验证引导；欢迎语与媒体 caption 统一采用纯文本语义，仅 `{name}` 占位符执行转义后替换，媒体发送失败不得把内部 JSON 配置回显给用户。
- 防止多管理员并发添加、删除列表配置或切换开关时发生丢失更新和基于旧索引删除错误条目。
- 重写关联冒烟测试，使 500 后重投真实复用同一 update；补齐相同 update 并发、限流与重投交错、话题 fencing、重开临时失败、管理员回复临时失败、重置后编辑、初始资料卡按钮、并发 nonce 和多管理员配置测试。
- 修正现有 OpenSpec 中 `esc()` 是否应转义反斜杠的矛盾：HTML 文本转义与 JavaScript 字面量转义保持职责分离。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `topic-relay`: 强化 update 幂等、500 重投、用户限流、双向消息送达、话题创建所有权、话题失效恢复、编辑消息和初始资料卡要求。
- `user-verification`: 强化验证开关即时生效、编辑消息门禁、nonce 原子性、普通首消息欢迎引导和上下文转义要求。
- `keyword-filter`: 将正则防护升级为不可由 `?`、转义括号等语法绕过的安全匹配契约，并要求编辑消息遵守过滤策略。
- `moderation`: 强化资料卡管理入口、黑名单话题 fencing、重置后编辑消息不可绕过验证，以及临时错误不得破坏共享话题映射。
- `admin-panel`: 明确欢迎语内容语义、媒体失败行为和多管理员并发配置修改的无丢失更新要求。

## Impact

- **代码**：主要影响 `worker.js` 的 update 处理、D1 schema/访问层、限流、Telegram API 客户端、话题创建与恢复、验证状态机、编辑消息、资料卡和管理配置路径。
- **数据库**：预计扩展 `processed_updates` 的处理状态与租约字段，并为话题 claim、配置版本或列表实体增加所有权/版本信息；需要幂等 schema 迁移。
- **测试**：重构 `smoke-test.mjs` 的原始 update 构造与故障注入，新增确定性的并发和迟到响应测试。
- **规格**：修改 `topic-relay`、`user-verification`、`keyword-filter`、`moderation`、`admin-panel` 五项能力，并纠正前一变更中的转义文字冲突。
- **依赖与部署**：安全匹配采用 Worker 内置的确定性安全子集解析与执行，不新增运行时依赖，维持 Cloudflare Dashboard 单文件部署。
- **兼容性**：不改变 Telegram 用户命令与管理员面板入口；数据库迁移必须兼容当前表中已有用户、话题映射和配置数据。欢迎语不再隐式解析 HTML，既有 `<b>` 等标签将按普通文本显示；不属于安全子集的既有 `re:` 条目将被拒绝匹配并在管理面板中标记为无效。
