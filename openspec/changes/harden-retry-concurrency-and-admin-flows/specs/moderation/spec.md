# moderation 增量规格

## MODIFIED Requirements

### Requirement: 手动屏蔽与解封

管理员点击资料卡上的屏蔽/解封按钮 MUST 切换该用户的屏蔽状态并重置违规计数；被屏蔽用户的消息 MUST 不再转发，用户收到屏蔽提示（短时间窗口内防抖只提示一次）；/start MUST 不解除屏蔽。

屏蔽入口 MUST 自话题创建起即可用：话题内首次发送的置顶资料卡 MUST 已经携带屏蔽/解封按钮，MUST NOT 要求管理员先执行其他操作触发资料卡刷新。

#### Scenario: 屏蔽用户

- **WHEN** 管理员点击某用户资料卡的"🚫 屏蔽"按钮
- **THEN** 该用户被屏蔽，资料卡按钮变为"✅ 解封"，其后续消息不转发

#### Scenario: 屏蔽用户尝试自救

- **WHEN** 被屏蔽用户发送 /start 或普通消息
- **THEN** 屏蔽保持不变，用户在防抖窗口内至多收到一次屏蔽提示

#### Scenario: 新话题首张资料卡即可屏蔽

- **WHEN** 用户话题刚被创建，管理员在未进行任何备注或屏蔽操作前点击置顶资料卡上的屏蔽按钮
- **THEN** 该用户被屏蔽，操作正常生效

### Requirement: 黑名单话题同步

用户被屏蔽（手动或自动）时，共享"黑名单"话题 MUST 生成含解封按钮的用户卡片；解封时该卡片 MUST 被删除；从资料卡或黑名单卡片任一入口操作，两处状态 MUST 保持一致。

黑名单共享话题在并发场景 MUST 只创建一次；创建占位 MUST 具备所有权标识，过期后被接管时原持有者 MUST NOT 覆盖新的话题标识，也 MUST NOT 释放他人持有的占位。共享话题被删除时 MUST 清空存储的话题标识并在下次需要时自动重建；被关闭时 MUST 先尝试自动重新打开，仅当重开因永久性错误失败时才按删除处理。限流、5xx、网络异常等临时性 API 错误 MUST NOT 触发标识清除或话题重建。

共享话题创建完成前允许本次卡片生成延后，屏蔽状态本身 MUST 即时生效。

#### Scenario: 屏蔽生成黑名单卡片

- **WHEN** 用户被屏蔽
- **THEN** 黑名单话题出现该用户卡片，含"✅ 解除屏蔽"按钮

#### Scenario: 黑名单话题解封

- **WHEN** 管理员点击黑名单卡片的解封按钮
- **THEN** 用户恢复正常，黑名单卡片删除，资料卡按钮同步变回"🚫 屏蔽"

#### Scenario: 黑名单话题被误删后自愈

- **WHEN** 管理员误删了黑名单话题，随后有用户被屏蔽
- **THEN** 系统自动重建一个新的黑名单话题并生成卡片

#### Scenario: 重开临时失败不清共享话题标识

- **WHEN** 黑名单话题被关闭，且重新打开操作因限流、5xx 或网络异常失败
- **THEN** 已存储的黑名单话题标识保持不变，系统不创建新的黑名单话题

#### Scenario: 过期持有者不得覆盖新共享话题

- **WHEN** 某次黑名单话题创建超时导致占位被接管，新持有者已写入话题标识，随后原请求才返回其创建结果
- **THEN** 当前生效的黑名单话题标识保持为新持有者创建的话题

### Requirement: 强制重置验证

管理员私聊发送 `/reset <用户ID>` MUST 将目标用户重置为未验证状态并作废其验证 nonce（不改变屏蔽状态与话题映射），同时通知目标用户重新验证；参数缺失或非数字时 MUST 返回用法说明。

重置 MUST 对该用户的全部入站路径生效：被重置用户在重新完成验证前，其新消息与对既有消息的编辑都 MUST NOT 被转达到管理群。

#### Scenario: 重置用户验证

- **WHEN** 管理员发送 `/reset 123456789`
- **THEN** 目标用户回到未验证状态，收到重新验证提示，管理员收到确认

#### Scenario: 参数错误

- **WHEN** 管理员发送 `/reset abc`
- **THEN** 返回用法说明，不做任何变更

#### Scenario: 重置后编辑消息不得绕过验证

- **WHEN** 已被重置的用户不重新验证，而是编辑一条此前发送的私聊消息
- **THEN** 编辑内容不被转达到管理群，用户收到验证引导
