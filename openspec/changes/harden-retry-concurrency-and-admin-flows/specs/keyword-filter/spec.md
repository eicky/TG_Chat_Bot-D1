# keyword-filter 增量规格

## MODIFIED Requirements

### Requirement: 匹配规则与正则防护

屏蔽词默认按不区分大小写的子串匹配；以 `re:` 前缀声明的条目按正则匹配。

正则匹配 MUST 以「仅接受可证明安全的模式」为准则，MUST NOT 依赖对已知危险写法的字符串黑名单。系统 MUST 解析 `re:` 模式并只接受受支持的安全语法子集；任何无法被解析、使用子集外语法、或无法保证匹配代价随文本长度线性增长的模式 MUST 被拒绝执行并视为不匹配。

安全子集 MUST 至少支持字面字符、字符类、`\d` `\w` `\s` 等常用转义、锚点，以及作用于单个字符或字符类的 `*`、`+`、`?`、`{m,n}` 量词，以覆盖常规屏蔽词用法。安全子集 MUST NOT 支持可产生歧义回溯的构造，包括作用于分组的量词、嵌套量词、反向引用与变长后行断言。

模式长度与被检文本长度 MUST 受限；被拒绝或非法的条目 MUST 视为不匹配、MUST NOT 报错、且 MUST NOT 影响同一列表中其余条目的匹配。转义字符 MUST 被正确解析，MUST NOT 因转义写法而使不安全模式被判定为安全。

#### Scenario: 子串匹配不区分大小写

- **WHEN** 屏蔽词为"SPAM"，用户发送"spam 消息"
- **THEN** 判定命中

#### Scenario: 正则条目匹配

- **WHEN** 屏蔽词为 `re:加微信\d+`，用户发送"加微信12345"
- **THEN** 判定命中

#### Scenario: 危险正则被拒绝

- **WHEN** 屏蔽词为 `re:(a+)+$` 这类高风险回溯模式
- **THEN** 该条目视为不匹配，其余条目正常生效，系统不超时不崩溃

#### Scenario: 无括号量词链被拒绝

- **WHEN** 屏蔽词为 `re:a*a*a*a*a*a*a*a*a*a*a*a*a*a*a*a*a*a*a*a*b` 这类无分组的连续量词链，用户发送可触发回溯的文本
- **THEN** 该条目视为不匹配，匹配过程不出现可观测的耗时增长，其余条目正常生效

#### Scenario: 可选量词链被拒绝

- **WHEN** 屏蔽词为 `re:a?a?a?…b` 形式的连续可选量词链，用户发送由同一字符组成的长文本
- **THEN** 该条目视为不匹配，匹配过程不出现可观测的耗时增长

#### Scenario: 转义括号不得绕过安全判定

- **WHEN** 屏蔽词为 `re:(?:a|aa|\))+$` 这类以转义右括号干扰结构判定的模式
- **THEN** 该条目视为不匹配，匹配过程不出现可观测的耗时增长

#### Scenario: 正常正则不被误伤

- **WHEN** 管理员配置 `re:[Vv][Xx]\s*[:：]?\s*\w+`、`re:客服\s*QQ\s*\d{5,}` 等含多个量词的常规屏蔽词
- **THEN** 这些条目正常参与匹配，不被安全判定拒绝

### Requirement: 屏蔽关键字拦截

用户消息文本（含媒体 caption）命中任一屏蔽关键字时，消息 MUST 不被转发，违规计数加一，并向用户发送含当前计数与阈值的警告。

违规计数 MUST 原子累加，并发命中 MUST NOT 导致计数丢失。屏蔽关键字策略 MUST 同样适用于用户对已发送消息的编辑内容。

#### Scenario: 命中屏蔽词

- **WHEN** 屏蔽词列表含"广告"，用户发送包含"广告"的消息
- **THEN** 消息不转发，用户收到"含有违禁词 (1/5)"式警告

#### Scenario: 编辑内容同样受拦截

- **WHEN** 用户把一条已发送的私聊消息编辑为包含屏蔽关键字的内容
- **THEN** 编辑内容不被转达到管理群，并按屏蔽关键字策略处理

## ADDED Requirements

### Requirement: 无效匹配条目的可见性

系统拒绝执行某个 `re:` 条目时，管理面板 MUST 在该条目上标示其未生效，使管理员能够察觉该规则不参与匹配。

#### Scenario: 面板标示被拒条目

- **WHEN** 管理员配置了一个不属于安全子集的 `re:` 屏蔽词，并在面板中查看屏蔽词列表
- **THEN** 该条目被标示为未生效，管理员可据此修改或删除它
